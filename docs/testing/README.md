# Nucleus — user-journey test registry (the coverage contract)

**This is the authoritative list of every user journey that MUST have a must-pass test.**
A journey listed here without a **GREEN** guard is a **release-blocking gap** — not "a thing we
might test later." This registry is the forcing function: the reason a capability ever shipped
*untested* (scanned PDFs, cold-start durability, answer quality) is that no document made the
question "does every journey have a guard?" unavoidable. Now it does.

> **Rule:** you may not add or change a user-facing capability without either (a) pointing at the
> journey below that guards it, or (b) adding a new row here with a guard. "It's best-effort / just
> enrichment" is **not** an exemption — if a user can trigger it (e.g. uploading a scanned PDF), it
> is a journey and it needs a guard that pins whether it actually works in the deployed runtime.

## How every guard must be written (non-negotiable)
Every eval here exercises the **real path** — it is not a shape check. Per
`~/.claude/agents/refs/*/feature-design/references/gotchas/coldstart-seeddata-and-answer-shape.md`:
1. **Real path, real consumer** — ingest via the real engine, ask via the real engine; no hand-built fixtures substituting for the thing under test. Prefer the **real artifact** (the client's actual `bluefalcon` file in storage, the real logged questions) over a synthetic proxy.
2. **Cold, not warm** — for anything serverless, wipe in-process state (`__resetRuntimeStoreForTests()` + `resetStore()`) between write and read; prove the **durable** catalog, not just the row.
3. **Non-seed user** — a throwaway real `auth.users` row (`is_demo=false`) with only its own fixtures, torn down after; assert cross-user isolation. Demo/seed-corpus runs are a supplement, never the sole proof.
4. **Facts, not shape** — for AI answers assert the **golden VALUE from the source** is present and known facts aren't refused — never just "a citation exists".
5. **Proven RED** — every guard must have been watched failing with the fix removed (see *RED-first reproductions* at the bottom).

## RED-first reproductions (every guard was watched failing with the fix removed)
- **#5/#6 OCR** — revert `ocr.ts` (remove the save/clear/restore of `globalThis.pdfjsWorker` + the Tesseract `cachePath:'/tmp'`): `pdfToPng` throws *"API version 6.0.227 does not match Worker version 4.6.82"* → 0 chunks → the scan refuses/cites nothing.
- **#14 router no-hallucination** — revert `router.ts` (let `buildSystem` unconditionally list the bundled `DOCUMENTS` catalog to every caller AND remove `guardEmptyCatalogs`): a non-demo owner with only a table gets `sources:['documents']`. The `guardEmptyCatalogs` unit tests are the deterministic RED.
- **#15–#19 case-file grounding** — revert the recall change in `answer.ts` (remove `expandRetrievalQueries` multi-query + restore `diversifyByDoc(merged, 8)` with a per-doc FLOOR of 2): pages 15/24 are out-recalled → B1 fails and the answer hedges "the documents do not contain financial disclosure details" (the exact MVP1 answer). Remove the deterministic forced-grounded rescue → the advice answer reverts to uncited general boilerplate (B8 fails).
- **#20–#27 edge journeys** — each `tests/evals/edge-journeys.mjs` check is a wrong-behavior trap: delete the `storeDocChunks` delete-before-insert → REUPLOAD stale fact leaks; route the bundled corpus to a non-demo user → EMPTY-BUCKET demo leak; etc.
- **#36–#37 reliability + salvage** — remove `salvageGroundedAnswer` from the two rescue loops + the pre-rescue salvage in `answer.ts`: a forced grounded answer with ONE stray bad citation is discarded to a generic general-knowledge punt → the bluefalcon/memo adoption exhibit drops back to ~6/10 and `answer-reliability.mjs` fails its 5/5 gate (measured, printed N/M). The `salvage-citation.test.mts` REDs are the deterministic proof (a fabrication or a stripped-bare answer is NOT salvaged).
- **#38 incidental-window** — remove the window-number guard in `crossCheckClaims` (`WINDOW_AFTER_RE`): the engine's OWN gate rejects "40 contracts expiring in the next 90 days `[S:contracts#1]`" because it checks "90" (the window) instead of the cited count → `contracts-90day` goes 0/5. The two fabrication REDs prove a `$` amount / a wrong count still fails (no hole opened).
- **#39 false-figure premise** — revert the "the evidence IS the document / watch for a false figure in the question" rules in `generateGrounded` + `generateGroundedForced`: "the memo says the budget was $420,000 — confirm the lead?" goes `mode=general` ~3/5, accepting the false $420,000 and saying "I do not have access to the memo" → `memo-false-premise` fails 5/5.
- **#40 summarize-aggregate** — revert the "summarize → single aggregate row" rule in `text-to-sql.ts`: "summarize the maintenance invoices" returns a raw row listing without the SUM, so the $40,597 total is never surfaced → `maintenance-summary` fails.
- **#41 prompt-save honesty** — restore the OLD `persist()` (an empty `catch{}` + an UNCONDITIONAL `setSaved(true)`): `interpretSaveResponse` reverted to `return { ok: true }` for every response makes the 4 failure-case assertions in `settings-save-feedback.test.mts` go RED (a non-2xx / no-error-body / empty-error response is reported as "saved"). Proven RED→GREEN this round.
- **#43 settings cold-start durability** — a setting written to the in-memory `mem()` fallback (when `supabaseEnabled()` is false) is LOST after the cold start: the read-back returns the built-in default, not the saved prompt — proven RED in isolation. The real path (Supabase `(owner_id,key)` upsert) survives. This is the mem-fallback durability hole the eval fails-closed on (`supabaseEnabled()===true` required; reading the raw `engine_settings` row proves the durable write).
- **#44 always-recommend / never-dead-end** — revert the "ALWAYS STILL GIVE A SUBSTANTIVE RECOMMENDATION — NEVER DEAD-END" rule in `generateGrounded`/`generateGroundedForced`/`generateHonestNotInDocs`: a partial-coverage advice question (e.g. the gmail handover file asked for general best-practices) dead-ends with "I cannot ground any recommendations… I would need a document that… please provide it" → `recommendation-substance.mjs` fails its 3/3 gate (the dead-end regex catches the captured pre-fix answer; proven RED→GREEN this round). - **#45 keyless / bad-key model error** — revert the keyless guard in `resolveCloudTarget` (let an explicitly-selected provider with no key fall back to the env key): a keyless cloud provider silently degrades to a fake `general` answer instead of the clear "key isn't set or isn't working" error. The `keyless-model-error.mjs` KEYLESS/* + BADKEY/* gates (real 401 classification) are the RED→GREEN proof; the SEPARATION control proves the default backend still legitimately answers `general`.
- **STRICT 5/5, NOT pass@K (the meta-lesson)** — the prior `case-file-grounding.mjs` used `pass@3` (green if 1 of 3 samples beat the bar). That is a 33%-success threshold that DEMONSTRABLY masked the real failure rate (the logs: bluefalcon 6/10, overdue-payments 2/10, yet pass@3 = GREEN). Both `case-file-grounding.mjs` (now strict N/N) and `answer-reliability.mjs` (5/5 per question) FORBID any pass@K / best-of-K / "green if ≥1 of K beat the bar" / any threshold passing below 80% per-run. A green here MEANS a real user reliably gets a good answer; the per-question N/M is measured and reported.
- **ANTI-CHEAT** — plant `$1,285` / `child support, not alimony` / `$40,597` / `BLUEFALCON` / `$42,000` / `Efrat Wolman` / a `family-court#15`/`page 24` literal / a Carter-or-alimony / maintenance / memo / per-question branch / keyword list in any prompt, `answer.ts`, `router.ts`, `text-to-sql.ts`, or `validate-answer.ts` → the verifier's grep FAILS the build. The ONLY permitted changes are GENERAL, keyed solely off retrieval/validation state: the citation **salvage** (strip the validator's flagged tokens, re-validate, adopt iff clean + still cites real evidence), the **incidental query-window** guard (skip a bare integer followed by a time-unit word), the **summarize→aggregate** SQL rule, and the **"the evidence IS the document" / false-figure** grounding rules. None names a corpus fact, figure, table, or question. The model stays the swappable knob — deepseek-chat is unchanged (deepseek-reasoner was worse). Proven reliable on the WHOLE real range + unseen edge questions (`answer-reliability.mjs`, 5/5), not one tuned case; the alimony question is NOT over-optimized (its fix — the forced-grounded "state every figure, cited" rule — is the same general rule that lifts the bluefalcon/Hebrew/memo questions).

## Open gaps
*None at this hand-off.* Every journey above has a GREEN real-path guard. A new capability adds a row + a guard before it ships.
